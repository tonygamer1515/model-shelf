Measured or read from each provider's own documentation. This table is the reason the page does not call itself unlimited.

Why there is no unlimited free model API

Inference costs money every time it runs — GPU-seconds, electricity, bandwidth. A provider can absorb that for a while to attract users, but nobody can offer it without a ceiling. So the honest choices are three:

OptionFree?Unlimited?Catch
Free hosted APIyesno Always rate-limited. This page uses these.
Self-host open weights$0 licenceyes You buy the hardware. The only truly unmetered route.
Paid APInopractically Metered by spend rather than by a daily cap.

Call it yourself

No library, no account for Pollinations.

image — keyless, 1 request per 15 s
curl -o fox.jpg "https://image.pollinations.ai/prompt/a%20red%20fox%20in%20snow?width=1024&height=1024&seed=7&nologo=true"
# HTTP 200, image/jpeg. access-control-allow-origin: *
# Go faster than one request per 15 s and the anonymous tier will refuse you.
chat — keyless, OpenAI-compatible
curl -X POST https://text.pollinations.ai/openai \
  -H 'Content-Type: application/json' \
  -d '{"messages":[{"role":"user","content":"Say OK"}],"seed":1}'
# {"choices":[{"message":{"role":"assistant","content":"OK","reasoning":"…"}}]}
Puter — 500+ models, no key for the site
<script src="https://js.puter.com/v2/"></script>
<script>
  // The visitor signs in to a free Puter account; Puter meters their usage.
  const reply = await puter.ai.chat("Explain SSE in one sentence.");
  const img   = await puter.ai.txt2img("a red fox in snow");
</script>
3D — keyless but ~1 asset/day (TRELLIS.2 Space)
RT=https://microsoft-trellis-2.hf.space
curl -X POST $RT/gradio_api/upload -F "files=@photo.png"
curl -X POST $RT/gradio_api/call/image_to_3d -H 'Content-Type: application/json' \
  -d '{"data":[{"path":"<uploaded>","meta":{"_type":"gradio.FileData"}},0,"512",
              7.5,0.7,12,5.0, 7.5,0.5,12,3.0, 1.0,0.0,12,3.0]}'
#   -> {"event_id":"219ccad8d2d64c49a03b23147b34a162"}
curl -N $RT/gradio_api/call/image_to_3d/<event_id>
#   -> event: error / data: null   once your 120 s daily reservation is gone
